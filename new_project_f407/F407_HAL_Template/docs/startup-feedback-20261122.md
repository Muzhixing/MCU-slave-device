# A75 与 B/C 回零反馈候选固件

本版基于 main `e58f9dc`（包含 `785123b` 航向恢复与四轮修正），目标 STM32F407VET6、8 MHz HSE。A 上电输出改为 75°；B/C 仍由驱动器执行其已有上电回零动作，STM32 新增只读 CAN 查询。未烧录、未上机验收。

**当前硬件条件尚未确认，因此这是待接线验收的候选包。** 用户不能确认两轴是否都装了 CAN 模块、CAN 是否接到主板。照片中的 X42_V1.3 / ZDT_CAN V1.2 是 PCB/模块标记，不能据此确定驱动器运行 Emm V5 还是其他固件。B 显示 1.3° / 1.32err / 0clk、C 显示约 0° / 0.00err / 0clk，不是回零完成标志。

## 本版如何建立零位

每轴独立经历：收到合规反馈 → 观察到回零进行中 → 编码器和校准就绪、回零停止且未失败 → 至少三份结束状态跨越 200 ms。只有 MCU 已禁用且脉冲已停止，才登记该轴零位。第一次收到“空闲”不会登记。

这确认的是**驱动器报告的一轮回零流程成功结束**。还必须现场核对该驱动器已配置的零点确实对应 B 顶部、C 完全收回。单圈编码器零点与多圈丝杆机械原点不是同一概念；本版没有增加原点传感器，也不通过撞限位寻找零点。

- 每 20 ms 轮询一轴，每轴约 40 ms。只发送 `0x3B` 查询，不发送运动、回零、清零或参数写入命令。
- 超过 500 ms 无合规反馈，或出现失败、未就绪、总线溢出/Bus-off，撤销零位依据；已使能时立即停止 MCU 脉冲及底盘输出，故障码 5。
- 一轮回零超过 30 s 不予确认；仍在回零时保持超时。重新获得空闲反馈不会恢复旧零位，需要新一轮可观察的回零过程。
- 通信恢复后，必须观察新回零周期，不能在已经移动的位置重新清零。
- 回零完成后仍持续查状态；脉冲位置仍是 MCU 估计值，本版不是电机绝对位置闭环。
- 旧 SW2 的 bit1/bit2 不再执行位置清零：只有对应轴已经验证且当前计数为零时可兼容接受；否则结果 7。
- MCU 无法用停止 STEP 脉冲取消驱动器自身正在执行的自主回零；自主动作的安全和结束由驱动器负责。

### 整机供电与仅复位 STM32

整机供电时，MCU 必须赶上两轴的“回零进行中”报告。若驱动回零太快或 MCU 启动较晚，可能错过事件，即使机构实际已归位也不会放行。

只重启 STM32 会丢失观察历史。驱动器没有重新回零、仅回复空闲时，本版保持零位未确认。这是协议缺少独立“本次已完成回零”锁存证据所致，不能靠固定延时补齐。验收时让 MCU 已运行后，再按硬件允许的供电顺序让驱动器执行已有回零流程；涉及驱动供电操作要按厂商接线要求进行，不带电拔插电机线。若现场无法保证观察到该周期，应先完善驱动反馈/启动同步条件，不把计数 0 当替代。

当前接口也没有独立驱动器上电计数：如果驱动器在两次查询之间极快复位并完成自主动作，且没有形成可观察的状态或反馈中断，本版无法识别该事件。可靠覆盖这种情况需要电源/复位指示或驱动器持久事件反馈，不能由本次轮询代码保证。

## 必要接线与参数

采用 **CAN1 的 PA11(RX)、PA12(TX)**。这是 MCU 逻辑侧，必须经过 CAN 收发器。没有确认现有线束已完成下面的连接。

|起点|终点|条件|
|---|---|---|
|STM32 PA12 / CAN1_TX|收发器 TXD|选逻辑侧适配 3.3 V 的收发器|
|收发器 RXD|STM32 PA11 / CAN1_RX|核实输出电平，不能把总线线缆直接接 MCU|
|MCU GND|收发器及两驱动通信地|按硬件手册建立参考地|
|收发器 CANH|B、C 模块 CANH|总线并联，按丝印确认|
|收发器 CANL|B、C 模块 CANL|CANH/CANL 不能对调|
|总线两物理末端|各 120 Ω 终端|先核实模块内置终端，避免重复；完全断电测 H-L 常见约 60 Ω|

不使用 PD0/PD1：它们已用于 C 方向与车轮驱动。原理图 PB8/PB9 周围的 CANH/CANL 标记不能直接当成可用 MCU 逻辑引脚；现有 TJA1050 电路是否可复用、PA11/12 的实际引出位置，需要现场核对。不能仅按线色接线。

两个电机都需要适配的 CAN 模块。兼容配置：B 地址 1、C 地址 2，500 kbit/s、扩展帧、固定校验字节 0x6B，`P_Serial=CAN1_MAP`。保留原 STEP/DIR 工作方式、细分、方向、回零模式及零点；不要为了配合本版更改为撞限位模式。先拍照记录现有菜单，核对实际驱动固件手册支持此组合。

选定的 Emm V5 兼容协议：查询 B 使用 ExtID `0x100`、数据 `3B 6B`；C 使用 `0x200`。响应必须为同一扩展 ID、三字节 `3B flags 6B`；flags bit0 编码器就绪、bit1 校准就绪、bit2 回零中、bit3 回零失败。本版拒绝高四位非零的其他协议变体。ZDT V2 等其他固件不能仅凭外观当作兼容。

来源：[厂家 Emm V5 Rev1.3 说明](https://devpress.csdn.net/xian/68945b69080e555a88d61cd3.html)，CAN 实现使用 [ST HAL v1.8.5](https://github.com/STMicroelectronics/stm32f4xx-hal-driver/tree/v1.8.5)，下载来源及哈希见 `Drivers/STM32F4xx_HAL_Driver/CAN_SOURCE.json`。

## 回传与诊断

原 10 字节下行及 20 字节上行 v1 保留。新增：

|位置|意义|
|---|---|
|状态 flags bit6 / bit7|B / C 最近 500 ms 有合规驱动反馈；不等于已回零|
|状态 flags bit1 / bit2|B / C 经过本版观察和登记的零位依据有效|
|结果 7|驱动回零未验证，或试图在非零位置用旧标志重新清零|
|系统故障 5|运行中驱动零位依据失效；与故障 1 的上位机通信问题区分|

调试器读取 `g_driver_can`（收发数量、拒绝、总线错误）、`g_axis_feedback[0/1]`（phase、epoch、flags、最近反馈时间）。phase 0 等待总线，1 等待回零事件，2 回零中，3 稳定确认，4 已验证，5 反馈失效，6 失败/未就绪，7 回零超时。此次没有增加新的遥测帧类型。

## 上位机配套

配套 bucket 分支修改只涉及启动和状态解释，检测、重获、遮挡暂停和圈内停止算法不变。旧固件位于原 C=10 工作位置仍可运行；新流程从 A75/B0/C0 起步，要求两轴零位及 CAN 新鲜标志、航向有效、机构已停止且无其他控制者。

若唯一故障为已停止时的历史通信故障 1，且上述新反馈条件满足、预检 UART 错误计数稳定，只发送一次禁用帧并等待成功确认；其他故障不自动清除。自动跟踪有新鲜目标后，先只移动 C 到 10 mm，保持 A75/B0；到位并收到停用确认后才进入 A/B 跟踪。目标消失或用户停止会中断 C 准备；C 在 0～10 mm 间中断后可从当前位置继续，不重新登记零位。不向机构发送启动 90° 命令。

## 明日验收顺序

1. 保留已可用旧固件以便回退；先核实两轴驱动协议、CAN 模块、参数与接线。不满足时不要把本候选当作已验证替换版。
2. 机构周围留出回零空间，底盘按现场测试要求隔离运动；用户自行烧录候选 HEX，HEX 带地址，BIN 基址为 `0x08000000`。本次未操作烧录器。
3. 先不运行自动运动程序，观察 A 上电到 75°。核对 B 顶部、C 收回确为驱动器回零终点；同时查看忙→结束反馈及两个零位位，不能只看位置数字0。
4. 若 flags bit6/7 缺失，检查协议/地址/收发器；若 bit6/7 有而 bit1/2 没有，检查是否错过回零过程或回零失败。不能用旧 `06` 命令绕过。
5. 单独重启 STM32，预期不从空闲直接恢复零位；重新建立完整可观察的回零周期。
6. 台架条件下验证反馈异常：停止状态先断开单轴反馈，零位应失效；恢复空闲回报不能自动重新置零。实际运动中的异常停机试验在前述条件通过后进行。
7. 使用配套上位机候选，观察 C 单独从 0→10、禁用确认，再允许 A/B 跟随；测试目标遮挡时暂停、居中停止调整。现有板端部署未更改，需在硬件验收后同步上位机候选才有此准备流程。

## 构建与验证

`SANITIZE=1 python3 tests/run.py`：主机模拟测试包含原协议、航向恢复、轮子控制逻辑、零位观察、CAN 报文/总线异常及运行中反馈失效停机。ASan/UBSan 开启。

`python3 tools/build.py --source . --out <输出目录> --toolchain <arm-none-eabi工具链bin目录>`：从 Keil 工程源列表生成 GNU 构建，保留原 98 项中断向量顺序。提供 HEX/BIN/ELF、源码哈希、构建日志。GNU 编译通过不代表 Keil 已重建，也不代表硬件回零验收通过。
