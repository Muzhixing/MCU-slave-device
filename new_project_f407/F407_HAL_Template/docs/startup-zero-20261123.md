# A73 上电与 B/C 自动准备

本修正在已验证的四轮滤波版本 `886b454` 上，将A上电命令从90°改为机械正中73°，并配套修改RK3588的启动识别。四路编码器滤波仍为15，PI、方向、故障处理、原10/20字节串口协议和B/C脉冲控制不变。

现场先试75°，用户确认略偏左；仅A调整至73°、B/C保持0并停车后，用户确认“已经居中”。本版以这次复核取代此前75°的机械零位约定。

## 自动准备的依据

当前硬件没有新增B/C回零完成反馈。B/C由驱动器执行已有的上电回零；RK3588按现场已确认的整机/电机共同重启约定，观察新鲜的A73/B0/C0、禁用、命令计数0和两轴零位未登记的组合状态，等待固定8秒，同时完成相机/模型预热和自检，随后只登记一次B/C软件零位。

8秒来自约5秒现场观察加3秒余量，是等待约定，不是MCU测得机械回零完成。普通程序重启或串口重连不会触发重新登记；登记发送后回传不确定时也不会重试。单独通过调试器复位MCU不证明电机已机械回零，调试/烧录后的登记测试须先核对B在顶部、C完全收回。

固件不按固定时间自行置零。RK3588未运行启动流程时，B/C仍保持“零位未登记”；该行为防止仅MCU复位时把未知机械位置自动变为零。此版本没有启用此前未确认接线和协议的CAN候选。

## 上位机配套

`arm_reference.json` 中 `mechanisms.A.structural_zero_command` 改为73，`power_cycle_startup.whole_power_on_pose` 改为 `[73,0,0]`。启动回正、自检返回点和页面提示都读取校准配置。启动识别、运行中复位识别、预检及登记确认均读取同一配置，不再写死90°。旧版90°固件仍可使用 `[90,0,0]` 配置；两种映像须配对配置。

保留已配置的A自检：0°→160°→73°，B/C目标均为0。若关闭该自检且A已是73°，不再为相同A目标额外使能底盘；登记后即可完成对应准备步骤。准备完成后，原流程等待新画面再跟踪。

## 验证状态

最终固件已用GNU Arm10.3.1编译并烧录，93个输入文件哈希已核对。相比四轮发布，唯一变化的运行输入是 `Hardware/Servo.h`；BIN长20136字节，SHA-256为 `a71097d52748721a7e3132516278cfeffbf3f5e5388ccb958c66b6f1a08b1e41`。

固件既有主机回归通过；上位机最终回归197项，191项通过、6项条件性跳过。新增覆盖73°/75°配置、等待期不发送命令、单次登记、重连保护及A自检返回校准零位。

最终映像校验及暂停读回一致；重启后A73、PWM脉宽1311µs、四路滤波0xF1F1、车轮PWM全0。用户确认“是，复位后仍然居中”。使用实际新固件的登记检验在首次稳定启动观察后8.030秒发送禁用，再仅登记一次，最终A73/B0/C0、禁用、错误0；普通串口重连不再识别为新启动。

证据：[校准反馈](validation/20261123-a73-startup/calibration-observation.json)、[烧录结果](validation/20261123-a73-startup/flash-result.json)、[登记检验](validation/20261123-a73-startup/preparation-result.json)、[检查范围](validation/20261123-a73-startup/review.json)、[发布映像](../firmware/20261123-a73-startup/README.md)。实机登记检验关闭A扫动并使用独立测试记录，没有启动完整视觉追踪；模型预热门槛与完整A自检由软件回归覆盖。

现场一次开关电源后仍保留命令计数2和原零位标志，未观察到MCU重启；随后明确的ST-Link复位重新产生启动状态。正常自动准备依赖MCU和驱动器实际共同重启，不能把开关操作本身当作已重启证据。是否有USB供电尚未定位。

本阶段要建立的认识是：新固件直接输出机械正中角度，上位机能够识别对应启动状态并完成原有自动准备。关键证据包括源码/映像哈希、串口时序、单次登记回传和现场A回正观察；真实回零完成反馈仍留待有相应硬件后实现。
