# 航向恢复与诊断

本改动修复 HWT101 接收异常后，正确角度帧恢复但连续航向一直无效的问题。恢复发生在控制输出已停止后；它不使能机构、不执行 B/C 置零、不自动继续旧目标。控制协议仍为原 10 字节 B3/B4 下行和 20 字节 B5/B6 v1 上行，原字段、长度、校验和 USART3 错误计数含义不变。

## 恢复行为

航向失效时停止底盘和步进脉冲，舵机保持。原始角度帧重新到达后，允许恢复原始角速度估计，但连续航向仍无效。控制器要求：

- 输出禁用、步进已停止。
- 原始角度数据年龄小于 300 ms，相邻观测样本间隔小于 300 ms。
- 至少 1 秒、至少 10 个不同序号的新样本。
- 角速度绝对值不超过 1°/s，角度相对稳定窗口起点变化不超过 1°。
- 稳定窗口内没有新的接收断续事件。再次出现异常、明显转动或过期数据会重新计时。

满足条件后，恢复相对原始零方向的模 360° 航向，再等待一个新的有效样本。**原航向零方向和控制器航向参考不改变**，不会把当前车头重新定义为 0°。数据缺口期间的完整转圈次数不可恢复，故累计角不作为可靠的多圈计数；现有控制器使用模 360° 方向。

数据恢复后仍处于 `HEADING_WAIT_ACK`，保持禁用。重新开始必须依次执行：

1. 从新回传确认航向有效、航向参考有效，读取当前位置。
2. 发送原协议 `SW2=0` 的停用帧，确认其命令计数、接受结果和禁用状态。
3. 由操作者重新开始，发送包含新目标的 `SW2=1` 帧。

恢复完成之前收到的停用帧不算重新开始的确认。持续发送旧使能帧，即使航向恢复，也不会自动执行。航向故障尚未清除时返回原结果码 4；故障已清除但尚未完成恢复/确认时返回原结果码 3。没有新结果码或新指令。

确认停用本身不运动。使能帧仍必须填写完整的航向、A、B、C 目标，不能把未操作轴随意填 0；中途停止的 B/C 脉冲位置和零点标志一直保留。上位机应让操作者重新开始，不能自行循环发送“停用→使能”来替人确认。

若传感器本体掉电并改变其自身航向基准，现有传感器帧与控制协议没有提供重启身份；本修复不能据此证明物理绝对方向仍正确。此时应重新核对方向参考后再人工开始，不应沿用旧的车辆转向任务。

## 不改变线协议的诊断

新增两个带 `version=1` 的内存诊断结构，由主循环更新并保留在 ELF 符号中：

```text
g_hwt101_diagnostics
g_heading_diagnostics
```

通过 Keil Watch 或加载对应 ELF 的 GDB/SWD 调试器读取。只读查看变量即可，不需要调用函数或改值。也提供 `HWT101_GetDiagnostics()` 和 `SystemControl_GetHeadingDiagnostics()`，供后续固件内部读取。

**这些细项不会自动出现在 RK3588 的旧 20 字节状态帧中。** 没有往现有串口混入文本、新帧或借用保留位；第 17 字节仍只统计 USART3 控制口错误。后续如需把详细诊断展示到 RK3588，需要另外设计明确兼容的读取方式。

`g_hwt101_diagnostics` 主要字段：

| 字段 | 含义 |
|---|---|
| `rx_bytes`、`last_rx_ms` | USART2 接收读数及最近接收时间 |
| `uart_errors` | 出现硬件串口错误的接收事件数 |
| `overrun_errors` / `framing_errors` / `noise_errors` / `parity_errors` | ORE / FE / NE / PE 分类计数；同一事件可包含多个错误位 |
| `queue_overflows` | 软件接收队列溢出数 |
| `valid_frames` / `angle_frames` | 校验正确帧数 / 有效角度帧数，区分“只有其他帧”与“角度正常” |
| `checksum_errors` / `frame_gap_errors` / `discarded_bytes` | 校验失败、帧内断续、解析丢弃字节 |
| `last_angle_ms` / `angle_age_ms` | 最近角度帧时间和年龄；未收到过角度帧时年龄为 `UINT32_MAX` |
| `discontinuities` / `recoveries` | 解析断续次数 / 已接受的连续航向恢复次数 |
| `last_break_reason` | 0 无、1 驱动串口错误、2 角度超时、3 队列溢出；保留最后原因 |
| `flags` | bit0 原始有效、bit1 连续角有效、bit2 原始角速度有效、bit3 连续角断续 |

`g_heading_diagnostics` 主要字段包括 `losses`、`recoveries`、`rejected_enables`、`stable_samples`、`stable_elapsed_ms`、`last_loss_ms`、`last_recovery_ms`、`raw_age_ms`、`stream_epoch`、`rearm_required`。`phase` 的含义：

| 值 | 阶段 |
|---:|---|
| 0 | 启动时等待建立参考 |
| 1 | 航向就绪 |
| 2 | 已停用，等待稳定新数据 |
| 3 | 连续性恢复，等待后续新样本 |
| 4 | 数据恢复，等待新的停用确认 |

典型定位：字节计数不增加，检查传感器输出和接线；字节增加但角度帧不增加，检查错误分类、校验及输出帧类型；角度帧增加且原始数据新鲜，但 `phase=2`，检查抖动、样本间隔及新的断续计数；`phase=4` 表示正在按设计等待操作者重新开始。

## 验证入口

在 `F407_HAL_Template` 目录运行：

```sh
python3 tests/run.py
CC=clang SANITIZE=1 python3 tests/run.py
```

测试使用原解析器、控制器和步进脉冲代码，仅模拟外设；编译文件放入临时目录并自动清除。覆盖原协议回归、非零 B/C 中途停机、80 次旧使能重发、停用确认时机、再次断流、运动中的传感器、仅陀螺帧、毫秒计数回绕、原航向参考保持、正负角边界，以及实际 USART2 驱动的错误分类和队列溢出路径。

目标编译使用原 Keil 工程中的源文件清单；没有新增必须手动加入工程的硬件 C 文件。新增诊断结构通过完整链接验证仍在 ELF 中。通过主机模拟和目标编译不代表已经完成实机接收干扰、恢复时延或运动验收；本次交付未烧录。
