# WT101 原始数据串口读取设计

## 1. 目标与范围

本阶段只验证 WT101 航向角寄存器的原始数据读取，并通过 USART2 周期输出可观测结果。

本阶段不启用四电机、航向 PID、麦克纳姆轮运动学、上位机命令解析，也不调整原工程中的传感器地址、寄存器、字节顺序或换算公式。

## 2. 硬件资源

### WT101（I2C1）

- SCL：PB6
- SDA：PB7
- 总线频率：100 kHz
- 7 位设备地址：0x50
- 航向角寄存器：0x3F

### 调试串口（USART2，TTL）

- TX：PA2
- RX：PA3
- 参数：115200、8 数据位、无校验、1 停止位
- 连接：开发板 PA2 接 USB-TTL 的 RX，PA3 接 USB-TTL 的 TX，双方 GND 共地

## 3. 数据读取规则

每次通过 I2C 从寄存器 0x3F 连续读取两个字节：

- 第一个字节为低字节 `L`
- 第二个字节为高字节 `H`
- 保留原工程无符号组合方式：`RAW = L | (H << 8)`
- 保留原工程换算公式：`YAW = RAW / 32768.0 × 180.0`

本阶段的重点是同时保留 I2C 读取状态、两个原始字节和组合后的原始值，避免读取失败被误报为有效的 0°。

## 4. 软件接口设计

WT101 驱动层的一次读取结果应包含：

- I2C/HAL 读取状态
- 低字节 `L`
- 高字节 `H`
- 组合值 `RAW`
- 按原工程公式计算的 `YAW`

应用测试层每 200 ms 调用一次读取接口并输出结果。上电初始化完成后等待 1000 ms，再开始第一次读取，以保持原工程的传感器启动等待行为。

所有新增或修改的源文件开头必须注明：引脚资源、使用外设、功能、用途和迁移来源。

## 5. 串口输出格式

读取成功：

```text
WT101 OK L=0x34 H=0x12 RAW=4660 YAW=25.59\r\n
```

读取失败：

```text
WT101 ERR=1\r\n
```

其中错误值用于区分通信失败，不输出伪造的 L、H、RAW 或 YAW 数据。

## 6. 错误处理

- I2C 读取失败时，本周期只发送错误行。
- 不将失败结果转换为 `YAW=0.00`。
- 单次失败不阻塞主循环；等待下一个 200 ms 周期后继续尝试。
- 本阶段不增加自动地址扫描、自动复位或参数重写，避免引入与原工程无关的行为。

## 7. 预期修改边界

实现阶段只允许修改 `new_project` 中与 WT101 驱动和 WT101 测试输出直接相关的文件，预计包括：

- `new_project/Hardware/WT101.c`
- `new_project/Hardware/WT101.h`
- `new_project/App/App_Test.c`
- 必要时同步更新上述模块直接依赖的文件头说明

`src` 和 `source` 目录继续作为原项目与资料参考，不做修改。现有电机测试参数和代码不做数据调整。

## 8. 验收步骤

1. 完整编译 HAL 工程，要求 0 Error、0 Warning。
2. 断开电机驱动或保持电机测试模式未启用。
3. WT101 与开发板共地并连接 PB6/PB7，USB-TTL 连接 PA2/PA3。
4. 打开 115200 8N1 串口，确认约每 200 ms 收到一行。
5. 静止传感器时，L/H/RAW/YAW 应保持在小范围内波动。
6. 缓慢旋转 WT101，确认 RAW 和 YAW 连续变化。
7. 断开 SDA 或 SCL，确认输出变为 `WT101 ERR=...`，而不是 `YAW=0.00`。
8. 恢复接线，确认后续周期能够自动恢复正常输出。
