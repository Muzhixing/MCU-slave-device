## 3. 原上位机串口协议迁移

原工程固定 10 字节二进制数据包保持不变：

```text
B3 forward_speed horizontal_speed target_angle rudder_angle
   lift_rod horizontal_rod switch_one switch_two B4
```

对应结构仍为：

```c
typedef struct
{
    uint8_t header;
    uint8_t forward_speed;
    uint8_t horizontal_speed;
    uint8_t target_angle;
    uint8_t rudder_angle;
    uint8_t lift_rod;
    uint8_t horizontal_rod;
    uint8_t switch_one;
    uint8_t switch_two;
    uint8_t footer;
} UART_Packet_t;
```

USART2 使用接收中断逐字节收集数据，校验包头 `0xB3`、长度 10 和包尾 `0xB4`。解析后仍按原逻辑赋值：

```text
forward_speed    -> motor_vx
horizontal_speed -> motor_vy
target_angle     -> target_yaw
```

舵机、升降杆、水平杆和开关字段继续保留在数据结构中；本阶段只接入底盘控制所需的三个字段，不擅自改变其他字段数值和排列。

## 4. WT101 UART 航向角数据

WT101 角度帧格式为：

```text
55 53 RollL RollH PitchL PitchH YawL YawH VL VH SUM
```

处理流程为：

1. 搜索帧头 `0x55`；
2. 接收完整 11 字节帧；
3. 校验前 10 字节累加和；
4. 只对类型 `0x53` 的角度帧提取 Yaw；
5. 将 `YawL/YawH` 组合成有符号 `int16_t` 原始值；
6. 使用原角度比例换算。

换算公式保持为：

```c
yaw = (float)yaw_raw / 32768.0f * 180.0f;
```

使用 `int16_t` 是为了正确保留 WT101 协议中的负航向角，不改变协议原始数据。

```text
        ↓

```

## 6. 原四轮运动计算

原麦克纳姆轮运动公式保持不变：

```c
speed_lf = vx - vy + omega;
speed_rf = vx + vy - omega;
speed_lb = vx + vy + omega;
speed_rb = vx - vy - omega;
```

其中：

- `vx` 控制前进和后退；
- `vy` 控制左右平移；
- `omega` 为航向 PID 产生的旋转修正量；
- 四个轮速继续交给当前已经验证的四路 HAL 电机接口。

该公式本身支持前后、左右、斜向和旋转组合，可以实现 360° 任意方向移动。例如 `vx` 与 `vy` 同时非零时，小车会沿相应斜向运动。

## 7. uint16_t、uint32_t 与 int32_t 决策

原封装函数为：

```c
void mecanum_with_heading_control(uint16_t vx,
                                  uint16_t vy,
                                  float target_yaw,
                                  float current_yaw);
```

`uint16_t` 和 `uint32_t` 都是无符号类型，不能表示后退或反方向平移所需的负速度。将 `uint16_t` 改成 `uint32_t` 不能解决方向问题，负数还可能被转换为很大的正数。

底层函数已经使用正确的有符号类型：

```c
void mecanum_move(int32_t vx, int32_t vy, float omega);
```

因此本次确定：

- 不修改原 PID 结构和运动公式；
- 不将速度改成 `uint32_t`；
- 后续蓝牙测试在独立测试文件中使用 `int32_t vx` 和 `int32_t vy`；
- 独立计算原 PID 输出 `omega` 后，直接调用原 `mecanum_move()`；
- 这样可以保留原工程逻辑，同时完整表达正负运动方向。

## 8. 江协科技蓝牙串口摇杆资料分析

`source\蓝牙串口信息` 中的 README 和截图确认，江协科技蓝牙串口小程序的摇杆使用 ASCII 文本数据包：

```text
[joystick,左摇杆X,左摇杆Y,右摇杆X,右摇杆Y]
```

启用短格式后为：

```text
[j,左摇杆X,左摇杆Y,右摇杆X,右摇杆Y]
```

示例：

```text
[j,0,-100,97,23]
```

数值可以为负数，因此单片机端必须以有符号类型解析。数据包使用 `[` 和 `]` 确定边界，使用逗号分隔字段。

### 8.1 已确定的摇杆功能

根据本次最终要求，摇杆定义为：

| 摇杆数据 | 功能 |
|---|---|
| 左摇杆 X | 左转或右转，并转换为航向 PID 的目标角度变化 |
| 左摇杆 Y | 暂不使用 |
| 右摇杆 X | 左右平移分量 `vy` |
| 右摇杆 Y | 前进/后退分量 `vx` |

控制数据流确定为：

```text
左摇杆 X
    -> 更新 target_yaw
    -> PID_Mulun_Calc(target_yaw, current_yaw)
    -> omega

右摇杆 X/Y
    -> int32_t vy/vx

vx + vy + omega
    -> mecanum_move()
    -> 四轮电机
```

因此：

- 左摇杆负责左右旋转和改变目标航向；
- 右摇杆负责前后、左右以及所有斜向平移；
- 平移过程中仍通过 WT101 和原 PID 修正航向；
- 原麦轮计算可以满足斜向和 360°平移要求；
- 蓝牙模块继续复用 USART2，不新增通信硬件接口。
