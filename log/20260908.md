# 2026-09-08 蓝牙控制双步进电机测试记录

## 当前工程状态

- 当前分支：`CANtest`
- 原工程目录：`src`
- 当前测试工程：`new_project`
- 主控：STM32F103C8T6
- 步进驱动器：X42 系列闭环步进驱动板，使用 Emm V5 协议
- CAN 收发器：外接 TJA 模块
- CAN 波特率：500 kbit/s
- 蓝牙模块：HC-08，等价于 TTL 串口
- 蓝牙串口：USART2，115200，8N1

本次工程用于验证蓝牙控制两台 CAN 步进电机是否可行。当前测试已经证明：STM32 能够接收蓝牙摇杆数据，并分别控制钢丝（丝杠）电机和横杆（齿轮）电机运动。

**当前参数是为了方便、安全地完成实物测试而设置的，不是最终整机配置。** 特别是钢丝速度、相对位置控制、摇杆距离映射以及 PA11/PA12 外接 TJA 的接法，后续整合四路底盘电机时需要调整。

## 蓝牙测试功能及可行性

蓝牙模块通过 USART2 向 STM32 发送摇杆数据：

```text
[j,LX,LY,RX,RY]
```

例如：

```text
[j,0,80,0,-60]
```

字段含义：

| 字段 | 含义 | 当前用途 |
| --- | --- | --- |
| `LX` | 左摇杆 X | 当前未使用 |
| `LY` | 左摇杆 Y | 控制钢丝电机上升、下降 |
| `RX` | 右摇杆 X | 当前未使用 |
| `RY` | 右摇杆 Y | 控制横杆左右移动 |

摇杆值范围按 `-100～100` 处理，死区为 `±20`。超过死区以后，摇杆幅度被映射为每条 CAN 命令移动 `1～5 mm`：

| 摇杆绝对值 | 单次移动距离 |
| ---: | ---: |
| 0～20 | 0 mm，不发送运动命令 |
| 21～40 | 1 mm |
| 41～60 | 2 mm |
| 61～80 | 3 mm |
| 81～100 | 5 mm |

当前使用相对位置模式。持续推动摇杆时，程序根据预计运动时间重复下发小段相对移动命令；摇杆回中以后停止继续下发命令。

实测结论：

1. HC-08 可以直接作为 USART2 的无线串口使用。
2. 左、右摇杆的数据能够被 STM32 分开解析。
3. 两台电机挂在同一组 CANH/CANL 上没有冲突，依靠不同 CAN 地址区分。
4. 钢丝和横杆均能独立运动，也能在同一程序中分别接收控制。
5. 钢丝电机上电无感归零已经验证可执行；归零等待期间程序暂时锁定蓝牙运动命令。

## 当前实测接线

### 蓝牙模块

| STM32F103C8T6 | HC-08 | 说明 |
| --- | --- | --- |
| PA2 / USART2_TX | RXD | STM32 发送到蓝牙 |
| PA3 / USART2_RX | TXD | STM32 接收蓝牙数据 |
| GND | GND | 必须共地 |
| 模块要求的电源 | VCC | 按 HC-08 模块板供电要求连接 |

串口逻辑为交叉连接，即 TX 接 RX、RX 接 TX。

### STM32与外接TJA CAN收发器

| STM32F103C8T6 | TJA模块 | 说明 |
| --- | --- | --- |
| PA12 / CAN1_TX | TXD | CAN控制器发送信号 |
| PA11 / CAN1_RX | RXD | CAN控制器接收信号 |
| 5V | VCC | 当前TJA模块供电 |
| GND | GND | 主控、收发器和电机驱动器共地 |

PA11、PA12 是 MCU 侧逻辑信号，不能直接接到电机驱动器的 CANH、CANL。

### TJA与两台步进驱动器

两台驱动器并联在同一条CAN总线上：

```text
TJA CANH ──┬── 钢丝驱动器 CANH/CHAN
           └── 横杆驱动器 CANH/CHAN

TJA CANL ──┬── 钢丝驱动器 CANL/CHAL
           └── 横杆驱动器 CANL/CHAL

GND     ───┬── 钢丝驱动器通信地
           └── 横杆驱动器通信地
```

驱动器丝印 `CHAN` 按 CANH 使用，`CHAL` 按 CANL 使用。两台驱动器的 CAN 接线和 8P 线束接法相同，不能靠调换线序区分电机，而是通过驱动器地址区分：钢丝地址1，横杆地址2。

8P接口继续沿用已经测试成功的原车线束和原插头方向。本工程没有可靠的8P插头针号与线色对照表，因此不能只凭线色重新制作线束；重做线束时应先用驱动板丝印或说明书逐针确认电源、GND、CANH和CANL，不能把动力电源接入CAN信号脚。

### 步进电机相线

电机四线端保持原接法：

```text
A+、A-：电机A相
B+、B-：电机B相
```

钢丝与横杆电机均沿用各自已经能正常上电复位和运动时的相线顺序。交换同一相的 `+/-` 会改变方向；不要把A相和B相随意混接。

CAN总线两端按实际拓扑保留120Ω终端电阻。断电测量CANH与CANL之间的总电阻时，两端各有一个120Ω终端的总线通常约为60Ω。

## CAN协议和数据格式

### CAN配置

STM32 CAN1当前配置：

```text
APB1时钟  = 36 MHz
Prescaler = 4
SJW       = 1 TQ
BS1       = 13 TQ
BS2       = 4 TQ
模式      = Normal
位速率    = 36MHz / 4 / (1 + 13 + 4) = 500 kbit/s
帧格式    = 扩展数据帧
```

扩展帧ID：

```text
ExtId = (电机地址 << 8) | 分包序号
```

例如地址1使用 `0x100、0x101...`，地址2使用 `0x200、0x201...`。

### 使能命令F3

完整Emm V5命令：

```text
[地址] F3 AB [使能状态] [同步标志] 6B
```

地址1立即使能：

```text
01 F3 AB 01 00 6B
```

CAN发送时地址字节进入扩展ID，数据区为：

```text
ExtId=0x100，Data=F3 AB 01 00 6B
```

### 位置命令FD

完整命令格式：

```text
[地址] FD [方向] [速度高] [速度低] [加速度]
[脉冲bit31..24] [bit23..16] [bit15..8] [bit7..0]
[相对/绝对] [同步标志] 6B
```

其中：

- `相对/绝对=0`：相对移动；
- `相对/绝对=1`：绝对位置；
- `同步标志=0`：立即执行；
- `同步标志=1`：等待多机同步触发。

命令长度超过一个CAN帧时，当前代码按每帧最多7个有效命令字节分包，并在每包首字节重复功能码。

### 速度命令F6

```text
[地址] F6 [方向] [速度高] [速度低] [加速度] [同步标志] 6B
```

当前蓝牙双步进测试主要使用FD位置命令，F6接口保留但不是本次摇杆控制的主要执行方式。

## 这不是最终配置

当前 `CANtest` 只用于验证CAN步进电机和蓝牙控制链路。它不能直接作为整车最终程序，原因如下：

1. PA11当前作为CAN1_RX使用，但四路底盘测试工程需要PA11输出右后电机PWM，两者直接冲突。
2. 当前摇杆每次只发送1～5mm相对运动，适合调试，但不等于最终机械目标位置控制。
3. 钢丝速度30 RPM是安全测试值，不是原工程最终值。
4. 当前没有同时运行四路底盘、HWT101、舵机、超声波和水泵。
5. 当前归零堵转电流和时间只经过现机构测试，仍需在完整负载下复核。
6. 当前移动范围主要依赖软件命令和驱动器归零，没有形成完整的上下限位安全链路。

## 最终工程建议配置

最终整合四路开环底盘时建议这样处理：

### 通信和引脚

- CAN1从PA11/PA12改为重映射PB8/PB9，并使用开发板板载TJA1050及CAN端子。
- 释放PA11，继续作为第四路底盘电机PWM。
- 蓝牙继续使用USART2：PA2/PA3。
- HWT101优先使用I2C1：PB6/PB7；如果I2C仍无法稳定通信，再改用USART1重映射PB6/PB7。
- 两台步进电机继续并联在同一CAN总线上，保持钢丝地址1、横杆地址2。

### 运动控制

- 保留已经验证的Emm V5底层协议和机械换算，不重写命令结构。
- 最终上位机仍以原工程十字节 `B3...B4` 数据包为主。
- 蓝牙摇杆包可以保留为人工调试/手动控制入口，但不能代替最终目标位置、安全限位和状态机。
- 最终钢丝恢复原工程100 RPM前，应先带实际负载逐级测试；横杆可先保留10 RPM。
- 最终位置控制应按原工程状态机使用明确的目标位置，并结合归零点建立有效行程。
- 钢丝、横杆都应增加软件上下限；条件允许时再加入物理限位或驱动器限位输入。
- 收到新目标前应检查归零是否完成、CAN是否有应答、目标是否超限，异常时发送停止命令。

### 最终验证顺序

1. 先验证PB8/PB9板载CAN能够分别控制地址1和地址2。
2. 验证钢丝归零后当前位置和运动方向正确。
3. 测量钢丝、横杆的实际最大安全行程并写入软件限制。
4. 恢复原工程绝对位置数据，逐点验证毫米和实际位移一致。
5. 接入四路开环底盘，确认PA11 PWM与CAN不再冲突。
6. 接入HWT101并验证航向数据，再进行整机状态机测试。
7. 最后测试蓝牙、CAN、底盘和HWT101同时运行时的供电、通信和急停逻辑。

## 当前结论

蓝牙控制双CAN步进电机方案可行，CAN接线、地址区分、Emm V5数据格式、钢丝毫米换算、横杆毫米换算和钢丝无感归零均已经得到实物测试支持。

当前代码应保留为 `CANtest` 分支的功能验证版本。最终整车程序需要首先解决PA11的CAN/PWM冲突，并把测试用的相对小步移动改回带归零基准、行程限制和状态机管理的目标位置控制。
